# 2026-08-02 · 흐름 · 저장 · 메인 화면

## 세션 범위

시작과 끝, 그리고 그 사이의 저장 흐름만 완성했다. 메인 컨텐츠 공정은 아직 데이터 구조가 미완성이라 라우팅 자리만 남겨 두었다.

신규: `GameFlow`(+`FlowTable`, `FlowEntry`), `flow.json`, `EndingStage`, `Cutscene_Ending` 씬 생성 메뉴.

수정: `StartMenuController` 전면 개편, `StartMenu.uxml` · `.uss`, `DataManager.UserDataCorrupted`, `cutscene.json`에 `ending` 추가, `dialogue.json`에 `ending_nojang` · `ending_ieumi` 추가.

추가 (같은 세션 후반): `PlaceholderProcess`, `PlayerPoseTracker`, `UserProgressData.PlayerPose`, 그리고 `IUM > Dev`의 `Create Flow Test Scene` · `Create Free Play Test Scene`.

기록 규칙은 [00 기록 규칙](00_기록_규칙.md)을 따른다.

## 처리한 이슈

- **ISSUE-009** (옵션 구성이 두 화면에서 다름) — 해결. 메인 화면도 `VolumeOptionsPanel`을 쓰게 되어 음악·대사·환경 세 항목으로 통일됐다. 마스터 볼륨 슬라이더는 제거했고 `UserSettingsData.MasterVolume` 값 자체는 남아 `DataManager.ApplyAudioSettings`가 계속 적용한다. 기획에서 마스터를 노출하기로 하면 UXML에 슬라이더 하나와 `VolumeOptionsPanel`에 바인딩 한 줄을 더하면 된다.

## 라우팅을 한 곳으로 모은 이유

`CutsceneDefinition`에는 목적지를 정할 수 있는 필드가 둘 있다. `completesProcess`(끝낸 공정을 기록)와 `nextScene`(끝나면 이동할 씬)이다.

둘 다 쓰면 같은 목적지를 컷씬 데이터와 흐름 데이터가 각각 지정하게 되어, 씬 이름이 바뀔 때 두 곳을 고쳐야 하고 어긋났을 때 어느 쪽이 이기는지도 불명확해진다.

그래서 이렇게 나눴다.

- **공정을 끝내는 컷씬**(프롤로그): `completesProcess`만 쓴다. `GameFlow`가 `CutsceneDirector.Finished`를 받아 갱신된 `NextProcess`로 보낸다.
- **진행과 무관한 컷씬**(엔딩): `nextScene`만 쓴다. 메인 화면 복귀는 라우팅이 아니라 그 컷씬 고유의 마무리다.

## 컷씬 오버레이 위에 남는 UI

프롤로그를 실행하면 메인 화면 UI가 컷씬 위에 그대로 남았다. 컷씬은 주 씬을 끄지 않고 겹쳐 올리는 구조라 StartScene이 살아 있고, UIToolkit 패널은 카메라와 무관하게 그려지므로 컷씬 카메라로 교체해도 사라지지 않는다. ISSUE-005에서 확인한 대로 `ScreenFader`의 uGUI 캔버스보다도 위에 놓여 암전으로도 가려지지 않는다.

`StartMenuController`가 매 프레임 `CutsceneDirector.IsPlaying`과 `SceneController.IsTransitioning`을 확인해 루트 엘리먼트의 알파를 내린다. 이벤트 구독이 아니라 폴링인 이유는 `OnEnable` 시점에 디렉터가 아직 없을 수 있고(Singleton은 첫 접근 때 생성된다), `Stop()` 같은 중단 경로와 씬 전환까지 추가 처리 없이 덮이기 때문이다.

처음에는 `display`를 한 프레임에 껐는데, 메뉴만 툭 사라지고 그 뒤에 남는 건 이미 거의 검은 카메라 배경이라 암전이 일어나는지 알 수 없었다. 지금은 컷씬의 `EnterFadeSeconds`와 같은 시간에 걸쳐 알파를 내리고, 0에 닿으면 그때 `display: None`으로 레이아웃과 피킹에서 뺀다. 되돌아올 때는 `OutroFadeSeconds`를 쓴다.

씬 전환을 조건에 넣은 이유도 같다. 전환은 페이더로 암전한 채 진행하는데 이 메뉴는 그 암전 **위에** 그려지므로, 그냥 두면 로딩 내내 떠 있다.

**앞으로 만들 화면 고정 UI에도 같은 문제가 생긴다.** HUD와 안내 UI를 붙일 때 컷씬 재생 중 처리를 함께 정해야 한다. 페이더가 UIToolkit 아래에 있는 한 각 패널이 스스로 물러나는 수밖에 없다.

## 컷씬이 라우팅한 뒤의 암전

`CutsceneDirector.UnloadStageAsync`가 `NextScene`이 비어 있으면 "뒤에 아무것도 없다"고 보고 `FadeIn`으로 화면을 되돌렸다. 그런데 바로 위 `Finished`에서 `GameFlow`가 이미 다음 공정의 씬 로드를 걸어 둔 경우가 있다 — 프롤로그가 그렇다. 암전이 풀리면서 로딩 중 화면이 드러나고, `SceneController`의 enter 페이드는 알파가 이미 0이라 아무 일도 하지 않았다.

`SceneController.IsTransitioning`이 참이면 페이드를 걸지 않는다. 전환이 화면을 넘겨받았다는 뜻이므로 암전을 유지한 채 넘긴다.

`nextScene`으로 목적지를 정한 컷씬(엔딩)은 원래부터 이 경로를 타지 않는다. 디렉터가 직접 `LoadScene`을 부르고 암전을 그대로 넘긴다.

## 흐름 테스트 씬을 새로 만든 이유

`StartScene`에는 `CutsceneView`, `SubtitleView`, `PauseMenuView`가 없다. 컷씬이 주 씬을 유지한 채 올라오므로 캡션, 건너뛰기 게이지, 대사 자막, 일시정지 메뉴는 전부 주 씬이 들고 있어야 하는데, 그 씬에서는 프롤로그가 아무것도 없는 검은 화면으로 재생된다.

`StartScene`은 손대지 않고 `Assets/@Scenes/Dev/FlowTest.unity`를 새로 만들었다. 구성은 Core Services(`SceneController` · `AudioManager` · `DataManager`), `GameFlow`, `CutsceneDirector`, Start UI, EventSystem, 그리고 위의 세 뷰다. 정적 데이터는 그대로 쓴다.

`PauseController.mainSceneName`은 이 씬에서만 `FlowTest`로 바꿔 넣는다. 다른 씬의 기본값 `StartScene`은 그대로다.

`cutscene.json`의 `ending.nextScene`도 `FlowTest`로 바꿨다. 이 값 하나가 컷씬 데이터에서 유일하게 씬 이름을 직접 들고 있는 곳이라, 메인 화면 씬을 교체하면 함께 옮겨야 한다. 정식 메인 화면 씬이 정해지면 여기와 `PauseController.mainSceneName` 두 곳을 그 이름으로 되돌린다.

## 자유 플레이 구간과 위치 저장

처음에는 메인 컨텐츠 자리를 아예 비워 두었다. 그 결과 프롤로그가 끝나면 목적지가 없어 메인 화면으로 되돌아왔고, 흐름이 한 바퀴를 돌지 못해 저장 기능을 검증할 구간 자체가 없었다. 자리표시자를 넣어 닫았다.

`flow.json`은 세 줄이 됐다.

```json
{ "process": "prologue", "cutscene": "prologue" }
{ "process": "tutorial", "scene":    "FreePlayTest" }
{ "process": "ending",   "cutscene": "ending" }
```

`completed` 항목은 뺐다. 엔딩 컷씬이 `clearsProgress`로 진행을 삭제할 뿐 `completesProcess`를 쓰지 않으므로 `Completed` 상태에는 도달하지 않는다.

`tutorial` 한 줄이 `tutorial ~ gongpoPuzzle` 여섯 공정을 전부 대신한다. `PlaceholderProcess`가 `Enter`로 그 구간을 한 번에 완료 처리한다. 하나씩 올리면 그다음 공정에도 목적지가 없어 같은 자리에서 다시 막히기 때문이다.

`PlayerPoseTracker`가 위치를 `UserProgressData.PlayerPose`에 싣는다.

- 씬 이름을 함께 저장하고 같은 씬일 때만 되돌린다
- `Vector3`·`Quaternion`이 아니라 float 넷으로 쓴다. Newtonsoft가 `normalized`·`eulerAngles` 같은 파생 프로퍼티까지 따라 들어가 문서가 자기 참조로 부푼다
- yaw만 쓴다. pitch와 roll은 VR에서 HMD의 것이고 데스크톱에서는 시점 모듈의 것이라 되돌리면 서로 싸운다
- 저장 시점은 셋이다. 씬을 떠날 때, 애플리케이션이 내려갈 때, 5초 간격 자동 저장. 앞의 둘만으로는 에디터 정지 버튼에 아무것도 남지 않는다
- `HasSaveData`가 거짓이면 쓰지 않는다. 엔딩이 진행을 지운 직후의 씬 전환이 그 삭제를 되돌리는 것을 막는다

전체 경로는 이렇다.

```
FlowTest → 게임 시작 → 프롤로그 컷씬 → FreePlayTest → Enter → 엔딩 컷씬 → 진행 삭제 → FlowTest
                                            ↑ ↓
                                   Esc → 메인 → 이어하기 (같은 자리로 복귀)
```

세 번째 화살표가 저장 왕복 검증이다.

## 미구현으로 남긴 것

실제 공정 씬이 생기면 `flow.json`의 `tutorial` 줄을 그 씬으로 바꾸고 나머지 공정을 한 줄씩 추가한 뒤 `PlaceholderProcess`를 뗀다. `PlayerPoseTracker`는 그대로 각 공정 씬에 두면 된다.

목적지가 없는 공정으로 진입을 시도하면 `GameFlow`가 경고를 남기고 `DestinationMissing`을 알린 뒤 화면을 유지한다. 화면에는 아무 표시도 나오지 않는다 — `StartMenuController`가 그 이벤트를 구독하지 않는다.

## ISSUE-013 · 완료 상태에서의 이어하기 동작이 문서에 없다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 해결됨 — 리드 프로그래머 결정에 따라 조치 |
| 위치 | `Assets/@Scripts/Cores/GameFlow.cs`의 `ClearProgress`, `Assets/@Scripts/Cutscene/CutsceneModels.cs` |
| 관련 | [02 화면·흐름·튜토리얼](../02_화면_흐름_튜토리얼.md) 1.5, 6.3 |

**증상**

모든 공정을 마치면 `NextProcess`가 `ProcessId.Completed`가 된다. `HasSaveData`는 `NextProcess != Prologue`이므로 이때도 참이고, 이어하기 버튼이 활성 상태로 남는다.

현재 `flow.json`은 `completed`를 엔딩 컷씬으로 매핑하고 있어, 완료 후 이어하기를 누르면 **엔딩을 다시 본다**. 문서에는 이 경우에 대한 기술이 없어 임시로 정한 동작이다.

**영향**

동작 자체는 자연스럽다(엔딩 다시 보기). 다만 의도한 설계인지 확인되지 않았다. 완료 후 이어하기를 비활성화하거나, 마지막 공정을 재플레이하게 하거나, 지금처럼 엔딩을 다시 보여주는 선택지가 있다.

**조치**

클리어 시 진행 데이터를 삭제하고 이어하기를 비활성화하는 것으로 정했다.

`CutsceneDefinition`에 `ClearsProgress`를 추가하고 엔딩에 켰다. 컷씬이 끝나면 `GameFlow`가 `UserProgressData.Reset()`을 호출하고 저장한다. `NextProcess`가 `Prologue`로 돌아가므로 `HasSaveData`가 거짓이 되어 이어하기가 꺼진다. 옵션 데이터는 `Reset`이 건드리지 않는다.

건너뛴 엔딩에도 적용한다. 엔딩까지 도달했다면 클리어이기 때문이다.

`CutsceneDirector`가 `Finished`를 `nextScene` 로드보다 먼저 쏘므로, 이어서 뜨는 메인 화면은 이미 삭제된 상태를 읽는다.

진행 삭제를 디렉터가 아니라 `GameFlow`에 둔 것은 진행 데이터를 쓰는 곳을 한 클래스로 모으기 위해서다.

## ISSUE-014 · app.json의 defaultGameplayScene이 쓰이지 않는다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 해결됨 — 리드 프로그래머 결정에 따라 제거 |
| 위치 | `Assets/@AddressableAssets/Data/Static/app.json` |

**증상**

개편 전 `StartMenuController`는 `targetSceneName`(기본값 `SampleScene`)을 직접 들고 시작 버튼에서 그 씬을 열었다. 이제 목적지는 `GameFlow`가 `flow.json`에서 결정하므로 그 필드를 제거했다.

`app.json`의 `defaultGameplayScene` 역시 같은 역할을 하려던 값으로 보이는데, 현재 이를 읽는 코드가 없다.

**영향**

동작에는 영향이 없다. 다만 목적지를 정하는 곳이 `flow.json` 하나여야 한다는 이번 정리의 취지와 어긋나는 값이 데이터에 남아 있다.

**조치**

`app.json`에서 제거했다. 목적지는 `flow.json` 한 곳에서만 정한다는 이번 정리를 데이터에서도 일치시킨 것이다.

`StaticDataModels.cs`에는 `app.json`에 대응하는 클래스가 애초에 없었다. `applicationId`, `contentVersion`, `startScene`, `supportedLanguages`도 마찬가지로 역직렬화 대상이 없으며, `StaticDataService`가 JToken으로 보관만 하고 아무도 `TryGet`하지 않는다. 앞으로 쓰일 여지가 있는 값이므로 남겨 두었다.

`app.json` 항목은 `manifest.json`에서 `required: true`이므로 파일 자체는 유지해야 한다.
