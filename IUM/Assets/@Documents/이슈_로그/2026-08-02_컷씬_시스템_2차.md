# 2026-08-02 · 컷씬 시스템 2차

## 세션 범위

5단계 진행 보조 기능 중 컷씬 시스템 구현. `Cutscene` 네임스페이스 전반, 컷씬 UI, 프롤로그 컷씬 씬, 테스트 씬 생성 메뉴.

건너뛰기 입력을 위해 `PlayerCommands`에 `Skip` 필드를 추가하고 `DesktopInputSource`(Space) · `XRInputSource`(오른손 Primary)에 매핑했다. 기록 규칙은 [00 기록 규칙](00_기록_규칙.md)을 따른다.

## 설계 전환 · JSON 스텝 러너에서 씬 오버레이로

세션 중간에 저작 방식을 바꿨다. 처음에는 `cutscene.json`에 스텝 목록(`Fade`/`Caption`/`Dialogue`/`Wait`/`Audio`/`Image`)을 적고 `CutsceneDirector`가 순회하는 구조였다.

전환 이유는 두 가지다.

1. **JSON이 씬 오브젝트를 참조할 수 없다.** Addressables 주소로 에셋은 가리키지만 씬 안의 특정 오브젝트를 지목할 수단이 없다. 에셋 GUID는 `.meta` 단위라 씬 파일 전체만 가리키고, 씬 오브젝트를 식별하는 `GlobalObjectId`와 `AssetDatabase`는 `UnityEditor` 전용이라 런타임 빌드에 없다. 오브젝트를 움직이는 연출을 넣을 방법이 구조적으로 없었다.
2. **편집 난이도.** `seconds`가 `kind`마다 의미가 달랐고, 필드 오타는 Newtonsoft가 조용히 버려 기본값으로 떨어졌으며, `wait` 조합이 만드는 동시성을 텍스트만 보고 재구성해야 했다.

바꾼 구조는 컷씬 한 편을 **씬 하나**로 만들고 `LoadSceneMode.Additive`로 주 씬 위에 겹쳐 올린다. 씬 안의 `CutsceneStage` 상속 컴포넌트가 연출을 담당하며, 오브젝트 참조는 인스펙터 직접 드래그로 해결된다. 제작자는 씬 에디터·Animator·Timeline·전용 스크립트를 그대로 쓴다.

`CutsceneDirector`에 남은 책임은 씬 로드·언로드, 입력 잠금, 건너뛰기, 진행 저장, 카메라 인계다. `cutscene.json`에는 컷씬 id와 씬 이름 매핑만 남았다.

`InputLockService`, `ProcessGate`, `DialoguePlayer`, `DialogueVoiceLibrary`, 자막, 건너뛰기 게이지는 그대로 살아남았다. 폐기한 것은 스텝 스키마와 스텝 러너다.

이 전환을 위해 `SceneController`에 `LoadAdditiveAsync` · `UnloadAdditiveAsync` · `IsAdditiveLoaded`를 추가했다. `ISceneEventListener`를 발생시키지 않는데, `OnSceneLoadStart`는 "현재 씬이 사라진다"는 뜻이라 리스너가 재생을 중단하기 때문이다. 컷씬 씬을 올리는 순간 그 컷씬이 스스로 멈추는 문제가 생긴다.

## ISSUE-004 · Addressables 초기화 핸들이 자동 해제되어 상태 확인에서 예외가 났다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 해결됨 — 이번 세션에서 조치 |
| 위치 | `Assets/@Scripts/Data/AddressableDataProvider.cs:22-32` |
| 관련 | `Assets/@Scripts/Data/DataManager.cs:41-73`, `Assets/@Scripts/Data/StaticDataService.cs` |

**증상**

`Addressables.InitializeAsync()`의 인자 없는 오버로드는 `autoReleaseHandle = true`로 동작한다(`AddressablesImpl.cs:426`이 기본값 `true`인 오버로드로 위임). 완료 시점에 Addressables가 핸들을 스스로 반납하는데, `await handle.Task`가 `UnitySynchronizationContext`를 거쳐 재개되는 사이에 그 반납이 먼저 일어난다. 이후 `handle.Status`에 접근하면 `Attempting to use an invalid operation handle` 예외가 발생한다.

`finally`에 `Addressables.Release(handle)`가 있는 것으로 보아 원 작성 의도는 수동 해제였으나, 호출하는 오버로드가 어긋나 있었다.

**영향**

`DataManager.InitializeInternalAsync`가 이 예외를 다시 던지므로 `IsReady`가 false, `Static`이 null로 남는다. 정적 데이터 전체(`app`, `dialogue`, `cutscene`)를 읽지 못한다. 대사와 컷씬은 로드를 try/catch로 감싸 두어 크래시 대신 빈 테이블로 뜨므로, 재생을 요청해도 아무 일도 일어나지 않는 상태가 된다.

발현이 타이밍에 좌우되어 이전 세션에서는 드러나지 않았다.

**조치**

`Addressables.InitializeAsync(false)`로 변경해 자동 해제를 끄고, 해제 책임을 기존 `finally`로 일원화했다. `ReadTextAsync`의 `LoadAssetAsync`는 자동 해제 대상이 아니므로 그대로 두었다.

요청 범위 밖이지만 데이터 로드 전체를 막는 문제라 원인과 수정안을 보고한 뒤 리드 프로그래머의 확인을 받고 조치했다.

## ISSUE-005 · UIToolkit 패널과 ScreenFader 캔버스의 렌더 순서가 검증되지 않았다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 해결됨 — 2026-08-02 실행 확인. 코드 변경 없음 |
| 위치 | `Assets/@Scripts/Cores/ScreenFader.cs:51-52`, `Assets/@Scripts/Editor/DevSceneBuilder.cs`의 `CreateCutsceneView` |
| 관련 | `Assets/@UI/Cutscene/Cutscene.uss`, [02 화면·흐름·튜토리얼](../02_화면_흐름_튜토리얼.md) 3.3 |

**증상**

프롤로그는 화면 암전 상태에서 "2008년 2월 10일" 캡션을 먼저 띄운다. 암전은 `ScreenFader`의 uGUI `ScreenSpaceCamera` 캔버스(`sortingOrder` 5000)이고 캡션과 자막은 UIToolkit 런타임 패널이라, 두 값이 같은 정렬 축에서 비교되지 않는다. 캡션이 암전에 가려질 수 있다.

`CutscenePanelSettings`의 `sortingOrder`를 6000으로 잡아 두었으나 이는 UIToolkit 패널끼리의 정렬 값이므로, 캔버스와의 상대 순서를 보장하지 않는다.

**영향**

가려질 경우 프롤로그에서 암전 중 캡션과 자막이 보이지 않는다. 암전이 풀린 뒤의 연출은 정상이다. 대사 테스트 씬은 암전을 쓰지 않아 영향이 없다.

**조치**

컷씬 테스트 씬 실행으로 확인했다. UIToolkit 패널이 `ScreenFader` 캔버스 위에 그려져 암전 중에도 캡션과 자막이 보인다. 코드 변경 없이 현 구성 그대로 둔다.

다만 이는 실측 결과이지 API가 보장하는 순서가 아니다. 렌더 파이프라인이나 `PanelSettings`의 렌더 모드가 바뀌면 다시 어긋날 수 있다. 그때는 `CutsceneView`에 자체 암전 레이어(전체 화면 `VisualElement`)를 두고 `Fade` 스텝을 그쪽으로 돌린다. 같은 패널 안이므로 순서가 결정적이 되고, `ScreenFader`는 씬 전환 전용으로 남는다.

## ISSUE-006 · 일시정지가 컷씬 진행을 멈추지 못한다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 해결됨 — [일시정지·옵션](2026-08-02_일시정지_옵션.md) 세션에서 조치 |
| 위치 | `Assets/@Scripts/Cutscene/CutsceneDirector.cs`의 `Update`, `Assets/@Scripts/Dialogue/DialoguePlayer.cs:114` |
| 관련 | [06 UI·저장·사운드·복구](../06_UI_저장_사운드_복구.md) |

**증상**

컷씬과 대사는 `Time.unscaledTime` 기준으로 진행하므로 `timeScale = 0`으로는 멈추지 않는다. 이는 의도한 설계다. `AudioSource`가 `timeScale`을 무시하고 계속 재생되기 때문에, 시간축을 맞추려면 틱 자체를 멈춰야 한다.

멈추는 쪽 코드가 아직 없다. 일시정지 메뉴가 들어올 때 `CutsceneDirector.Update`와 `InGameDialogue.Update`의 틱을 중단시키는 연결이 필요하다.

**영향**

일시정지 메뉴가 아직 없어 현재 드러나지 않는다. 그대로 두면 컷씬 도중 일시정지 시 화면만 멈추고 음성과 자막이 계속 흐른다.

`InputLockFlags.Cutscene`에 `Pause`를 넣지 않아 컷씬 중 일시정지 입력 자체는 이미 허용되어 있다(F-003 3.4).

**조치**

당초 방향이었던 "틱 중단"은 불충분해서 시간 소스 자체를 바꿨다. 틱만 멈추면 `Time.unscaledTime`은 계속 흐르므로, 10초 일시정지 후 재개하면 재생 중이던 줄의 종료 시각이 이미 지나 있어 자막이 건너뛰어진다. 반면 `AudioListener.pause`는 음성을 정확히 그 자리에 세워두므로 둘이 어긋난다.

`PauseService.Now`를 도입했다. 일시정지 구간을 뺀 무스케일 시각이라 메뉴가 열려 있는 동안 그냥 멈춘다. `DialoguePlayer`, `CutsceneDirector`, `PrologueStage`가 모두 이 시각을 쓴다.

`CutsceneStage`에는 `ShouldTick`을 두어 파생 클래스가 진입에서 한 번에 거르게 했다. 시간 기반이 아닌 프레임 처리(불꽃 흔들림 등)를 멈추기 위한 것으로, 시간 정확성은 `Now`가 따로 담당한다.

`CutsceneDirector.Update`는 일시정지 중 즉시 반환한다. 페이즈 시간은 `Now`로 이미 멈추지만 건너뛰기는 그렇지 않은데, `Skip`이 의도적으로 `InputLockFlags` 밖에 있어 메뉴가 열린 상태에서도 게이지가 차기 때문이다.

## ISSUE-007 · 컷씬 카메라 교체의 VR 안전성이 검증되지 않았다

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-02 |
| 상태 | 미해결 — 실기기 검증 항목 |
| 위치 | `Assets/@Scripts/Cutscene/CutsceneDirector.cs`의 `TakeOverCamera` · `RestoreCamera` |
| 관련 | `Assets/@Scripts/Cutscene/CutsceneStage.cs`의 `StageCamera`, [01 공통 규칙](../01_공통_규칙.md) |

**증상**

컷씬 씬이 자체 카메라를 선언하면 디렉터가 주 씬 카메라를 끄고 그것으로 교체한다. VR에서는 플레이어가 움직이지 않았는데 시점이 이동하는 것이라 멀미를 유발할 수 있다.

암전 상태에서 교체하도록 순서를 잡았고 `enterFadeSeconds`가 그 시간을 준다. 그러나 HMD 착용 상태에서 실제로 견딜 만한지는 확인하지 못했다.

**영향**

데스크톱에서는 문제가 없다. 실기기에서 불편하면 컷씬을 카메라 교체 없이 주 씬 시점을 유지하는 방식(스테이지가 `StageCamera`를 비우고 제자리에서 연출)으로 바꿔야 하며, 그 경우 프롤로그처럼 다른 장소를 보여주는 컷씬의 연출 방식을 다시 잡아야 한다.

또한 URP의 카메라 스태킹은 XR에서 제약이 있으므로, Overlay 카메라를 쓰는 방향으로 확장할 때 별도 확인이 필요하다.

**조치 방향**

실기기 확보 후 프롤로그를 착용 상태로 재생해 확인한다. 불편하면 암전 시간을 늘리거나, XR Origin을 그대로 두고 컷씬 오브젝트를 플레이어 주변에 배치하는 방식으로 바꾼다.
