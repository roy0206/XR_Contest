# PROJECT 이음 - 이슈 로그 기록 규칙

## 1. 폴더 목적

구현 과정에서 발견했으나 해당 작업의 범위 밖이라 즉시 수정하지 않은 사항을 기록한다.

핵심 제약의 "요청 범위 밖의 문제는 직접 수정하지 않고 위치와 내용만 보고한다"에 따라 보고한 내용을 남긴다. 보고 후 잊히는 것을 막고, 다음 작업자가 같은 문제를 다시 발견하는 비용을 없애는 것이 목적이다.

## 2. 파일 규칙

- 작업 세션마다 파일 하나를 만든다. 기존 파일에 이어 쓰지 않는다.
- 파일명은 `YYYY-MM-DD_주제.md` 형식으로 한다. 같은 날 세션이 둘 이상이면 주제로 구분한다.
- 이슈 번호는 `ISSUE-001`부터 폴더 전체에서 이어서 매긴다. 세션마다 다시 시작하지 않는다.
- 해결한 이슈는 원래 파일에서 지우지 않고 상태만 바꾸고 해결 커밋을 덧붙인다. 해결 작업을 한 세션의 파일에도 어느 이슈를 처리했는지 남긴다.

## 3. 항목 형식

이슈마다 다음을 남긴다.

| 항목 | 내용 |
|---|---|
| 발견일 | 발견한 날짜 |
| 상태 | 아래 상태 구분 참고 |
| 위치 | `파일:줄` 형식. 줄 번호는 발견 시점 기준이므로 변경될 수 있다 |
| 관련 | 함께 봐야 하는 파일이나 문서 |
| 증상 | 무엇이 잘못되어 있는지 |
| 영향 | 지금 무엇이 깨지는지, 무엇은 안 깨지는지 |
| 조치 방향 | 어떻게 고칠 수 있는지. 확정된 계획이 아니어도 된다 |

## 4. 상태 구분

| 상태 | 의미 |
|---|---|
| 미해결 | 조치하지 않음. 조치 시점 미정 |
| 조치 예정 | 담당 작업 또는 시점이 정해짐 |
| 해결됨 | 조치 완료. 해결 커밋을 함께 기록 |
