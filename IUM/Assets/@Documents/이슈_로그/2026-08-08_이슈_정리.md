## ISSUE-001을 어느 쪽으로 고쳤는가

원 기록의 조치 방향은 둘이었다. `L` 키를 `InputLockService` 기반으로 바꾸거나, `InGameDialogue`가 생겼으니 `L` 자체를 제거하거나. 원 기록은 후자가 단순하다고 봤다.

전자를 택했다. `L`은 노장 시스템이 없는 씬에서 PTT 잠금 반응을 확인하는 유일한 수단이다. 제거하면 `InGameDialogue`를 배치한 씬에서만 잠금 검증이 가능해지는데, `AiVoiceTest`는 이음이 단독 씬이라 그 경로가 사라진다. 개발 도구를 없애는 대신 올바른 경로에 태우는 편이 낫다.

바뀐 것은 세 줄이다.

```csharp
IDisposable _pttLock;                       // bool _locked 대체

if (_pttLock == null)
    _pttLock = InputLockService.Acquire(InputLockFlags.PushToTalk, "노장 대사 (디버그)");
else { _pttLock.Dispose(); _pttLock = null; }
```

이제 `AiConversationManager.SetInputLocked`를 부르는 곳은 `PushToTalkLockBridge` 하나다. 브릿지의 주석이 처음부터 명시한 설계 — 두 직접 호출자가 있으면 먼저 끝난 쪽이 잠금을 풀어버린다 — 를 디버그 스위처만 위반하고 있었다.

참조 카운트에 올라갔으므로 겹침도 자연스럽게 처리된다. `L`이 켜진 상태에서 대사가 재생되고 끝나도 카운트가 1로 남아 PTT는 잠긴 채고, 반대로 대사 재생 중 `L`을 꺼도 대사 쪽 홀드가 남아 열리지 않는다.

`OnDisable`에서 토큰을 해제한다. 없으면 컴포넌트를 끈 뒤에도 카운트가 남아 그 씬에서 PTT가 영영 잠긴다. 놓아 줄 주체가 사라지기 때문이다.

## 믹서 자산이 없다

ISSUE-002를 처리하려다 확인한 것이다. 프로젝트 전체에 `.mixer` 자산이 하나도 없다.

```
find Assets -name "*.mixer"   →  결과 없음
```

`AudioManager`의 `mixer`, `sfxGroup`, `bgmGroup` 필드(`AudioManager.cs:16-18`)는 참조만 선언되어 있고 대상 자산이 존재하지 않는다. `ApplyVolume`이 `mixer.SetFloat`를 부르는 경로도 마찬가지로 대상이 없다.

따라서 ISSUE-002는 "DIALOGUE 채널 추가"가 아니라 **믹서 자산 신규 생성 + MASTER·BGM·SFX·DIALOGUE 네 채널 구성 + 노출 파라미터 정의**가 된다. 믹서는 공용 자산이라 별도 승인이 필요하고, 원 기록의 계획대로 옵션 UI(F-002) 작업과 함께 다루는 편이 맞다.

원 기록의 "믹서 채널은 MASTER, BGM, SFX 세 개뿐이다"는 코드상의 의도를 적은 것이고, 실제로는 그 셋도 연결되어 있지 않다. 옵션 UI 작업 시 이 점을 전제로 잡아야 한다.
